What this guide covers · Key highlights

The parts where most people get stuck

The WordPress MCP setup has several non-obvious requirements. This guide documents every one of them so you don't have to figure them out yourself.

Authentication
Application Password security — no plugins required
WordPress Application Passwords are built into core since version 5.6. The guide covers exactly how to create one, name it, and use it securely with Claude Desktop.
Built-in WordPress feature — no extra installs
HTTPS & local sites
Application Passwords require HTTPS — workaround documented
WordPress disables Application Passwords on plain HTTP by default. If you're on a local or HTTP site, the guide includes the exact filter to re-enable them safely.
Common blocker — fix included
REST API
Verify your REST API is live before configuring anything
Some hosts or security plugins disable the REST API by default. The guide shows you how to test it first — so you're not troubleshooting a config that was never going to work.
Test first, configure second
Site config
The wp-sites.json file — every field explained
The site config file is the most common failure point. The guide covers every required field, the exact format, and the one key that's easy to miss and causes silent failures.
Silent failure — documented fix
Apache hosts
Authorization header stripped on Apache — .htaccess fix included
Many shared hosting providers running Apache strip the Authorization header before it reaches WordPress. The guide includes the exact .htaccess line to add and where to put it.
Affects many shared hosting setups
Troubleshooting
Every common error — with exact fixes
Hammer icon not appearing, 401 authentication errors, connection refused, REST API disabled — each error is documented with the exact solution and why it happens.
Full troubleshooting section
